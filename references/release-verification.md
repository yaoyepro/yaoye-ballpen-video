# 1.0.1 发布核验（2026-10-13）

本次把用户提供的 1.0.1 安装包整理为 GitHub 项目。原始功能源码保持不变；README 增加下载和反馈入口、英文简介及验证范围，并去掉未经核实的同系列项目入口与绝对化表述。

## 文件与环境

- 原始 ZIP：79 个文件，SHA256 `e7ef6ac3fb2443607928ed241363becc08298b9fff25492c53ba035a38326d4b`。
- 保留 MIT、随包字体 OFL 与第三方说明；扫描未发现实际密钥，出现的 GEMINI_API_KEY 是环境变量名称。
- 13 个 Python 文件通过语法解析，JSON 文件可解析。
- 本机 Windows 10 / Python 3.12.10 / Node 26.7.0 / skia-canvas 3.0.8 / FFmpeg 9.0.1。
- 安装 skia-canvas 后，`doctor` 输出 ALL GOOD；这仅证明依赖检查通过。

## 实际通过

- `examples/theme_sun` 生成场景计划。
- 从该示例实际渲染 3 秒和 10 秒处静帧，并检查中文、笔记本背景及圆珠笔元素。
- 生成 2 秒 H.264 测试片：1920×1080，15 fps，30 帧，FFmpeg 完整解码无错误。

## 已知限制

- 当前本机的 `build` 命令在输出阶段异常退出，错误为 `scene build failed`，未获得可解释的标准错误；直接 chunk 命令虽写出有效视频文件，进程仍以非零状态结束。根因本次未确认。因此**不能把本次测试理解为 Windows 完整制作流程通过**。不建议在此环境直接开始长片，先做短样片。
- Windows 首次检查还出现 Python subprocess 默认 GBK 解码异常；本次用进程级 `PYTHONUTF8=1` 后通过依赖检查。没有改变系统全局编码设置。
- 新版 npm 若阻止 skia-canvas 安装脚本，需要检查并允许该官方 npm 依赖的安装脚本；不要不加判断地允许所有依赖脚本。
- 本次未重新测试 macOS、Linux、全部四种风格、歌曲识别对齐、所有音乐模式和长视频最终混音。原包兼容文档中的 Linux 测试描述来自原作者随包材料。
- 测试短片无音轨，不能作为音频效果的验证。

以上是有限范围的发布前检查。仓库上传、下载与权限另由发布操作复盘记录。发现问题时请提交系统版本、复现步骤及脱敏报错。
